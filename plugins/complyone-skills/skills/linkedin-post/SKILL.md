# LinkedIn post: ComplyOne.io

Write the post, check it against every rule below, then show it. A post that breaks a rule is not ready, however good it reads.

## 1. Before drafting

- **Audience.** Default is a general business audience (founders, SME owners, operations leads). Only treat it as specialist (compliance officers, a webinar audience, a white paper) if the request says so.
- **The one point.** One idea per post. If you can't state it in a sentence, ask before drafting.

## 2. Hard rules (each one has been broken before)

| Rule | Detail |
|---|---|
| Our name | Always **ComplyOne.io**: that casing, with the .io. Never "ComplyOne", "Complyone", "COMPLYONE" or "Comply One" |
| Jargon (general audience) | Only **compliance** and **GDPR** may appear as technical terms. No DPA, DPO, Art. 28, NIS2, DORA, AMLR, MiCA, ROPA, FADP, EnEfG, ESRS, CSRD, or article numbers. Say what the rule does in plain words instead. Specialist audience: jargon allowed |
| Claims | Never "validated", "certified", "guaranteed", "bank-ready" or "audit-ready". Say *readiness* or *structured obligation coverage* |
| Customers | Never name or hint at a real customer, prospect or partner, or use their data. Use an invented example and say it is one |
| Numbers | Every figure needs a source you have actually read. No invented statistics, no "studies show" without the study |
| Credibility | Never use our build time (for example "built in 3 months") as a selling point |
| Voice | Founder: William Hannah, Founder. Plain, honest, no hype, no emojis unless asked. Honest about where we are |

## 3. Legal and regulatory claims: verify before showing

Any sentence saying what a law requires, who it applies to, how something is classified, or when it takes effect:

1. Check it against a **primary source** (the regulation's text, an official regulator page) before the draft is shown. Recall is a first draft, never the answer.
2. If it can't be verified, soften it to what is known, or flag it for review. Never publish an unverified specific legal claim as fact.
3. Show the source with the draft: name it and give the passage relied on.

## 4. Shape

- Hook: a question or concrete situation in the first line (it shows before "see more").
- 150–300 words, short paragraphs, one blank line between them.
- Optional: a 3-item checklist ("1 —", "2 —", "3 —").
- End with one question to the reader.
- 3–5 hashtags, always including #compliance.

## 5. Output

1. The post text, ready to paste.
2. Then a block headed `NOTES (do not paste):` listing each legal claim, the source checked, the date, and anything softened or removed.
3. If working inside the `head_architect` repo, save both to `sales/linkedin posts/YYYY-MM-DD_<short-slug>.txt`.
4. Translations (DE / FR) only on request, and translate the checked English version, never a draft.

## 6. Final check (run it, don't assume it)

- [ ] "ComplyOne.io" spelled exactly, everywhere
- [ ] General audience: no jargon beyond compliance and GDPR
- [ ] None of the banned claim words
- [ ] No real customer, prospect or partner
- [ ] Every number and legal claim has a source in NOTES
- [ ] One idea, ends on a question, has hashtags
